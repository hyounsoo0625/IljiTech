## 3. CQI 점수 자동 산출

### 계산 방법

- 첨부1로 18개 지표의 월별 실적을 계산하고, 첨부3의 점수 수식을 그대로 적용했습니다. 목표·배점·수식은 코드에 적어 두지 않고 첨부3 파일에서 읽어 오므로, 목표가 바뀌면 첨부3 파일만 바꾸면 됩니다.
- 자동으로 계산하는 범위는 고객 35점, 공정 25점, 협력사 20점, 합계 80점입니다. 예방품질(10점)과 품질비용(10점)은 첨부3에 입력된 값을 더해 100점 총점을 만들었습니다. 26년 9월부터는 `data/manual/수기입력_CQI.csv`에 입력하면 됩니다.
- 점수 수식은 첨부3과 같습니다.
  - 역수형 (고객 지표, 입고불량, LOT 발생률): 실적이 목표 이하면 만점, 목표의 2배면 절반
  - 선형 (공정불량 PPM, 폐기비, 재작업비, 유출률): 목표와 같으면 배점의 70%, 목표보다 30% 이상 좋으면 만점, 목표의 1.7배 이상이면 0점
  - 초도형 (초도합격률): 목표(99.9%)와 같으면 70%, 100%면 만점. 첨부3 수식에 하한이 없어 99.67% 미만이면 음수가 됩니다.

### 실적 계산 기준

메일과 집계기준에 적힌 내용을 바탕으로, 첨부3 값과 하나씩 맞춰 보면서 정리한 기준입니다.

| 지표 | 계산 | 첨부3과 비교 |
|---|---|---|
| 고객불량(등록 PPM), 고객등록률 | 고객등록 0건이므로 0 | 일치 |
| 고객실질 PPM | 고객실질 시트 전체(본사+경주) 수량 $\div$ 고객 납품수량 $\times$ $10^6$ | 1~8월 일치 |
| 공정불량 PPM | (폐기 + 수정 수량) $\div$ 공정 생산수량 $\times$ $10^6$ | 블랭크·프레스·조립 1~8월 일치 |
| 초도합격률 | 100 - 공정불량 PPM $\div 10^4$ (블랭크·프레스 소수 2자리, 조립 3자리) | 일치 |
| 폐기비 / 재작업비 | 구분이 폐기 / 수정인 기록의 금액 합 | 일치 |
| 프레스 유출률 | A $\div$ (프레스 불량 건수 + A), A는 조립 불량 중 귀책처가 생산1과·원자재인 건수 | 7월 외 일치 |
| 조립 유출률 | B $\div$ (조립 불량 건수 + B), B는 고객실질 중 공장구분이 본사인 건수 | 1~7월 일치 |
| 입고불량 PPM | 협력사 불량 수량 $\div$ 협력사 입고수량(반품 포함) $\times$ $10^6$ | 1월, 4~7월 일치 |
| LOT 발생률 | LOT 건수 $\div$ 협력사 불량 건수 $\times$ 100 (수량이 빈 7/30 길창 건은 제외) | 일치 |

## 5. "AI 분석 평가" 문구 (1번 슬라이드)

이번 달 결과를 과거 추이와 비교해 원인을 설명하는 문장으로 보고 작성했습니다.

### 작성 방법

1. CQI 변화를 지표별 점수 변화로 나눴습니다. CQI는 지표 점수의 합이므로 정확히 나뉩니다.
2. PPM처럼 나눗셈으로 구하는 지표는 점수 변화를 다시 "불량 수량이 바뀐 몫"과 "생산·납품·입고 수량이 바뀐 몫"으로 나눴습니다. 어느 쪽을 먼저 바꾸느냐에 따라 결과가 달라지지 않도록 두 경우를 평균했습니다(섀플리 값).
3. 점수가 크게 바뀐 지표는 원천 기록을 공장·라인·차종·불량유형·귀책처·협력사별로 전월과 비교해, 변화의 가장 큰 몫을 차지한 항목을 찾았습니다.
4. 지표마다 최근 12개월 중 가장 좋은지 나쁜지, 몇 개월 연속 나빠졌는지 확인했습니다.
5. 이 결과를 정해진 문장 틀에 넣어 문구를 만듭니다. 문구를 만드는 데 생성형 AI는 쓰지 않습니다.

### 설명가능 AI 모델 검토

"어떤 요인 덕분에 개선되었는지"를 모델로 설명할 수 있는지도 시험해 봤습니다.

- 결정트리는 CQI 값 자체는 비교적 잘 맞혔습니다(한 달씩 빼고 학습해 그 달을 맞혔을 때 평균 오차 0.8점). 하지만 가장 큰 원인을 산식 분해와 같게 짚은 횟수는 결정트리 0번, 랜덤포레스트 0번, Ridge 1번이었습니다.
- 8월의 가장 큰 요인인 물량 효과(−7.1점)는 세 모델 모두 찾지 못했습니다.

CQI는 정해진 산식으로 계산되는 점수이고 지금은 데이터가 8개월뿐이어서, 모델보다 산식을 그대로 나누는 쪽이 정확했습니다. 그래서 문구는 위의 규칙 기반 방식으로 만들고 담당자가 검토하는 방식을 제안합니다. 데이터가 2~3년 이상 쌓이고 4M 변경 이력 같은 원인 데이터가 생기면, CQI 대신 불량 발생 자체를 설명하는 모델로 다시 검토해 볼 수 있습니다.

## 6. 영역별 상관분석

첨부4의 항목에 따라 영역별로 어떤 불량이 어디서, 언제 많이 나는지 봤습니다. 블랭크는 첨부4에서 제외되어 있어 분석하지 않았습니다.

분석 방법
- 두 기준(예: 프레스 라인 × 불량유형)으로 건수 표를 만들고, 기록을 무작위로 섞었을 때와 비교해 관계가 우연인지 검정했습니다. p값이 0.05보다 작으면 우연이 아닌 것으로 판단했습니다.
- 칸마다 "관계가 없다면 기대되는 건수"와 실제 건수를 비교해서 유난히 많은 조합을 찾았습니다.
- 수량은 LOT성 불량 한 건이 크게 반영되므로 건수(기록 수)를 기준으로 했습니다.

### 고객 (본사·경주 통합, 130건)

- HMC 공장별로 많이 나는 유형이 다릅니다. 3공장 너트분리(6건, 기대 1.5건), 1공장 PART오조립, 5공장 볼트체결불가, 2공장 굴곡.
- 다만 공장마다 받는 차종이 거의 정해져 있어(LX3 → 2·4공장, NX4 → 5공장, SX2 → 1공장, CN7·QX → 3공장) 공장 차이의 상당 부분은 차종 차이입니다. 차종으로 보면 QX 너트분리(5건, 기대 0.5건), LX3 굴곡, SX2 SPOT용접스패터가 두드러집니다.
- 발생 시기(월, 상·중·하순, 요일)는 공장별로 뚜렷한 차이가 없었습니다. HMC 5공장만 상순(1~10일) 발생이 많은 편입니다(19건, 기대 11.7건).

### 프레스 (본사, 600건)

- 라인별로 많이 나는 유형이 뚜렷하게 다릅니다.
  - P-1: T/O 86건 (기대 27건)
  - P-5: 크랙 101건 (기대 61건)
  - P-4: 형상불량 74건 (기대 51건)
  - P-3: 주름
- 원자재 귀책 비율은 P-1 73%, P-3 72%, P-5 74%, P-4 57%, P-2 16%입니다. P-1·P-3·P-5는 코일 LOT 변경 이력과 함께 보면 원인을 더 좁힐 수 있을 것으로 보입니다.
- 라인별로 불량이 몰린 달이 다릅니다(P-5는 25.12월 32건, 26.1월 26건, 26.5월 27건). 월 안에서의 시기(상·중·하순)와는 관계가 없었고, 프레스 전체 생산량과의 관계도 뚜렷하지 않았습니다.

### 조립 (본사, 107건)

- 조립 불량 데이터에 라인 정보가 없어 차종 기준으로 봤습니다.
- CN7(56건)은 형상불량·크랙이 많고 절반이 협력사 귀책입니다. US4(7건)는 조립불량·네크가 많고, 7건 중 4건이 개발·생산기술 귀책입니다.
- 분리시험·샘플용 폐기(품질팀 파괴시험, 고객 요청 샘플)도 조립 공정불량에 포함되어 있습니다. 12개월 동안 14건이고, 26년 8월에는 조립 불량 12EA 중 6EA가 분리시험이었습니다. 공정불량 PPM에 포함하는 것이 맞는지 확인이 필요합니다.
- 프레스 불량이 많은 달의 같은 달이나 다음 달에 조립 불량이 늘어나는 관계는 확인되지 않았습니다.

### 협력사 (본사, 227건)

- 업체별로 많이 나는 유형이 있습니다. 성지산업 네크(4건, 기대 0.7건), 성심정밀 BURR(6건, 기대 1.7건), 우영산업 변형.

첨부4의 예측 항목 세 가지를 다음 달 사전 점검 목록 형태로 만들었습니다.

### 방법

- 품번(라인, 협력사)마다 지난 기록으로 최근 3개월 건수, 최근 달에 가중치를 둔 건수, 최근 6개월 중 불량이 난 달 수, 마지막 불량 이후 지난 개월 수, 같은 라인·협력사의 최근 건수 같은 값을 만들고, 다음 달 불량 여부(라인·협력사는 건수)를 맞히도록 학습했습니다. 예측하려는 달 이후의 기록은 쓰지 않았습니다.
- 품번 예측에는 모델 7종(로지스틱 회귀, 결정트리, 랜덤포레스트, 엑스트라트리, 그래디언트 부스팅 2종, 단조 제약 부스팅)을, 라인·협력사 순위에는 건수 예측 모델 6종(Ridge 회귀, 포아송 회귀, 트리 계열 4종)을 썼습니다. 각각 모델을 섞은 앙상블과 "최근에 많이 난 순" 같은 단순 규칙까지 같은 조건에서 비교했습니다.

평가 지표의 뜻
- 적중률@K: 매달 점검 목록 K개 중 실제로 불량이 난 비율의 평균
- 포착률@K: 실제로 불량이 난 대상(과거 불량 이력이 있는 것) 중 목록에 들어 있던 비율
- AP (평균 정밀도): 위험 순위 전체가 얼마나 잘 맞는지. 1에 가까울수록 좋고, 무작위면 실제 불량이 난 비율과 같음
- AUC: 불량이 난 대상을 안 난 대상보다 위에 둘 확률. 0.5면 무작위
- 순위상관 ρ (Spearman): 예측 건수 순위와 실제 건수 순위가 얼마나 같은지. 1이면 완전히 같고 0이면 관계없음
- 상위 3개 적중: 예측 상위 3개 중 실제 상위 3개에 든 비율
- MAE: 예측 건수와 실제 건수 차이의 평균

## 9. 설치 및 활용 가이드

### 설치

Python 3.11에서 실행을 확인했습니다. conda를 쓰는 경우 아래 순서로 환경을 만듭니다.

```bash
conda create -n project python=3.11
conda activate project
pip install numpy pandas scipy scikit-learn matplotlib openpyxl python-pptx ipykernel
python -m ipykernel install --user --name project --display-name project
```

마지막 줄은 VS Code나 Jupyter에서 `project` 커널을 고를 수 있게 등록하는 명령입니다. conda 없이 일반 가상환경(venv)을 써도 같은 패키지를 설치하면 됩니다.

실행을 확인한 패키지 버전입니다.

| 패키지 | 버전 |
|---|---|
| pandas | 3.0.6 |
| numpy | 2.4.6 |
| scipy | 1.17.1 |
| scikit-learn | 1.7.2 |
| matplotlib | 3.11.2 |
| openpyxl | 3.1.5 |
| python-pptx | 1.0.2 |

pandas 2.3에서도 실행됩니다. python-pptx가 없으면 PPT 작성만 건너뛰고 나머지는 그대로 실행됩니다.

그래프의 한글은 Apple SD Gothic Neo, 나눔고딕, 맑은 고딕, Noto Sans CJK KR 중 설치된 글꼴로 표시합니다. Windows에는 맑은 고딕이 기본으로 있어 따로 설치할 필요가 없습니다.

### 처음 실행할 때

1. 받은 자료를 아래 폴더 구성처럼 `data/raw/데이터/`와 `data/raw/추가전달자료/`에 넣습니다.
2. 노트북은 `요구사항.md`가 있는 폴더를 프로젝트 폴더로 인식합니다. 이 파일을 지우면 실행이 멈추므로, 내용을 빼더라도 같은 이름의 파일은 남겨 두어야 합니다.
3. VS Code나 Jupyter에서 `analysis/main.ipynb`를 열고 커널을 `project`로 고른 뒤 전체 실행(Run All)합니다. 1분 정도 걸립니다.
4. 터미널에서 실행하려면 `pip install nbconvert`로 nbconvert를 설치한 뒤 `analysis` 폴더에서 아래 명령을 씁니다.

```bash
jupyter nbconvert --to notebook --execute --inplace main.ipynb
```

### 매월 할 일

1. 첨부1과 같은 형식의 불량 데이터를 `data/raw/추가전달자료/<받은 날짜>/`에 넣습니다. 한 달치 파일도 됩니다. 같은 달이 여러 파일에 있으면 가장 최근 파일을 씁니다.
2. 협력사 입고수량은 SAP 입고 리스트 파일(`협력사입고수량*.xlsx`)을 `data/raw/` 아래에 넣거나, `data/manual/협력사입고수량_월별.csv`에 월 합계를 적습니다.
3. 예방품질·품질비용은 `data/manual/수기입력_CQI.csv`에 적습니다.
4. `analysis/main.ipynb`를 처음부터 끝까지 실행합니다. 데이터의 가장 최근 달이 보고 월이 되고, 다른 달을 보려면 노트북 위쪽의 `REPORT_MONTH`를 바꿉니다.
5. `output/`의 결과를 확인하고, PPT 상세표의 개선방안·일정을 작성합니다.

데이터가 없어 계산하지 못한 칸은 비워 두거나 첨부3 값을 쓰고 출처를 표시합니다. 해당 데이터가 들어온 뒤 다시 실행하면 직접 계산한 값으로 바뀝니다.

### 설정 바꾸기

노트북 0-1 셀의 값을 바꾸면 됩니다.

- `REPORT_MONTH`: 비워 두면(`None`) 데이터의 마지막 달로 보고서를 만듭니다. `'2026-07'`처럼 적으면 그 달 기준으로 만듭니다.
- `USE_COMPANY_VALUE_IF_MISSING`: `True`면 원천 데이터가 없는 칸을 첨부3 회사값으로 채우고, `False`면 비워 둡니다.
- `CQI_YEAR`: 첨부3이 다음 해 파일로 바뀌면 연도를 바꿉니다.

### 실행이 안 될 때

- `필수 파일이 없습니다`: 첨부1이나 첨부3을 찾지 못한 경우입니다. 파일 이름에 `불량 데이터`, `CQI`가 들어 있는지, `data/raw/추가전달자료/` 아래에 있는지 확인합니다.
- `StopIteration`: 프로젝트 폴더에 `요구사항.md`가 없는 경우입니다.
- `시트가 없어 건너뜀` 메시지: 첨부1의 시트 이름이 바뀐 경우입니다. 노트북 1-3 셀의 `ATT1_SHEETS`에서 시트 이름을 고칩니다.
- `PermissionError`: Windows에서는 결과 엑셀이나 PPT 파일을 열어 둔 채 실행하면 덮어쓰지 못합니다. 파일을 닫고 다시 실행합니다.
- 그래프의 한글이 네모로 나오는 경우: 위의 한글 글꼴 중 하나를 설치하고 커널을 다시 시작합니다.
